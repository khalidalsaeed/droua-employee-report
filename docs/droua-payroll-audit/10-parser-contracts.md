# عقود القرّاء — ما يلزم لكتابة قارئ PDF أو Excel

> **لا تخمين لتنسيق ملفّاتنا.** هذا المستند يصف ما يجب أن يُخرجه أي قارئ،
> وأين يتّصل، وكيف يُقاس صدقه — كي لا يبقى إلا استخراج النصّ يوم تصل عيّنة.

## 1 · الخطّ الكامل

```
بايتات مشفَّرة
   ↓ storage.getDecrypted        (فكّ + وسم + AAD + بصمة)
بايتات صريحة
   ↓ parsers.parse({format, kind, bytes})
   ↓   ├─ csv.js        ✅ جاهز
   ↓   ├─ xlsx.js       ✅ جاهز — ZIP + XML، بلا اعتماد
   ↓   ├─ xls.js        ✅ جاهز — OLE2 + BIFF8، بلا اعتماد
   ↓   └─ pdf.js        ⏳ هيكل يُعلن عجزه
   ↓        كلّها تنتهي إلى csv.normalizeRows(kind, header, dataRows)
جدولٌ مطبَّع { kind, rows, meta }
   ↓ compare.compare({docs, previousDocs})
ملاحظات
```

**نقطة الاتّصال واحدة:** `normalizeRows`. القارئ الجديد مسؤول عن شيء واحد —
تحويل الملفّ إلى **صفّ ترويسة ومصفوفة صفوف نصّية** — ثمّ يسلّمها. ومنطقُ
أسماء الأعمدة وتطبيع الأرقام واقتطاع الحساب مكتوبٌ مرّة واحدة ولا يُعاد.

> ولو كتب كل قارئ تطبيعه لتباعدت ثلاث نسخ بعد سنة، ولأنتجت مقارنةً تكذب على
> صيغةٍ دون أخرى — وهو عطلٌ لا يظهر إلا حين يُرفع الشهر بصيغة مختلفة.

## 2 · العقد المطلوب من القارئ

```js
module.exports = {
  format: "pdf",
  available: true,
  parse({ kind, bytes }) {
    const { header, dataRows } = extract(bytes);   // ← وحده ما يُكتب
    return csv.normalizeRows(kind, header, dataRows);
  },
};
```

* `header` مصفوفة نصوص: أسماء الأعمدة كما ظهرت في الملفّ.
* `dataRows` مصفوفة مصفوفات نصّية، بترتيب الأعمدة نفسه.
* لا يحسب شيئًا، ولا يفسّر رقمًا، ولا يقتطع حسابًا — كلّه في المطبِّع.

## 3 · ما يُخرجه المطبِّع

```js
{
  kind,
  rows: [Row],
  meta: {
    source, rowCount, warnings,
    mapping,           // { field: "اسم العمود في الملفّ" }
    unknownColumns,    // أعمدة لم تُطابق أي مرادف
    confidence,        // 0..1
    needsManualReview, // ثقة دون العتبة، أو حقلٌ مطلوب غائب
  }
}
```

### الثقة — ولماذا لا تُخفى

```
الثقة = (المطلوب المفهوم × 2 + المفيد المفهوم) / (المطلوب × 2 + المفيد)
العتبة = 0.67 · وأي حقلٍ مطلوب غائب يرفع العلم مهما ارتفعت النسبة
```

والحقول المتوقَّعة **لكل نوع على حدة**:

| النوع | مطلوب | مفيد |
|---|---|---|
| كامل | `empNo`, `net` | `name`, `basic`, `allowances`, `deductions` |
| تحويل | `empNo`, `net` | `name`, `iban`, `bank` |
| كاش | `empNo`, `net` | `name` |
| قائمة الموظفين | `empNo`, `name` | `jobTitle`, `status`, `iban` |

> قياسُ الجميع بقائمةٍ واحدة كان يهبط بثقة ملفّ الكاش السليم — رقمٌ واسمٌ
> وصافٍ لا غير — إلى النصف، ويرفع علم «يحتاج مراجعة» على ملفٍّ لا عيب فيه.
> **وإنذارٌ كاذب في نظام تدقيق أسوأ من صمت: يدرّب المستخدم على تجاهل
> التنبيه.**

### وما يظهر للمستخدم

* `needsManualReview` ⇒ ملاحظة **حرجة**: «قراءةٌ ناقصة تحتاج مراجعة».
* `unknownColumns` ⇒ ملاحظة **معلومة** واحدة تسرد الأعمدة — لا واحدة لكل
  عمود، فعشرون ملاحظة تُغرق ما يهمّ.
* `warnings` ⇒ ملاحظة لكل تحذير: عمود مطلوب غائب، عمودان لحقلٍ واحد، رقم
  موظّف مكرّر.

## 4 · قواعد لا تُخرَق في أي قارئ

1. **`empNo` نصًّا لا رقمًا** — الأصفار البادئة جزءٌ من المفتاح.
2. **رقم الحساب يُقتطع إلى أربع خانات عند القراءة** (`lastFour`). الرقم
   الكامل لا يغادر الملفّ المشفَّر ولا يبلغ أي بنية في الذاكرة.
3. **لا تخمين لموضع عمود.** إن لم يُطابق اسمُ العمود مرادفًا فهو
   `unknownColumn` — لا «العمود الثالث غالبًا الصافي». وقارئٌ يخمّن يُنتج
   أرقامًا خاطئة **تبدو صحيحة**، وتُبنى عليها ملاحظات ثمّ قرارات.
4. **الفشل يُعلَن** بـ`ParserUnavailable` أو تحذير — لا يُبتلع في صفر.

## 5 · قارئا Excel — ما بُني ولماذا بلا مكتبة

**القرار: بلا اعتماد خارجيّ.** مكتبة قراءة تجرّ مساحةً وسلسلة توريد كاملة
إلى مشروعٍ يقرأ أربعة ملفّات في الشهر — وكلفتُها الحقيقية ليست حجمها بل أنها
تصير **بابًا ثالثًا إلى بيانات الرواتب**. وما لزم منها أقلّ من ثمان مئة سطر
موصوفة في مواصفتين مفتوحتين.

**`xlsx.js`** — حاوية ZIP (يفكّها `zlib` في Node) وXML. وثلاث مزالق:
النصوص تعيش في `sharedStrings.xml` والخليّة تحمل فهرسًا إليها؛ والخلايا
**متفرّقة** ومرجعها في `r="C7"` لا في ترتيبها — فقراءتها بالتسلسل تُزيح
الأعمدة عند أول خليّة فارغة، وتُنتج أرقامًا صحيحة في أعمدة خاطئة تبدو
سليمة تمامًا؛ والتواريخ أرقامٌ متسلسلة لا تُحوَّل بالتخمين.

**`xls.js`** — حاوية OLE2 (جدول تخصيص قطاعات، ودليل، ومجرًى صغير) ثمّ
سجلّات BIFF8. وأخطر مزلقٍ فيها **جدول النصوص الممتدّ على `CONTINUE`**: كل
امتداد يبدأ ببايت سماتٍ جديد قد يغيّر الترميز في منتصف النصّ — ومن يتجاهله
يُخرج النصّ العربيّ حروفًا لاتينية مبعثرة. ويليه فكّ `RK`: عددٌ محشور في 32
بت، وخطؤه يُنتج مبالغ أكبر مئة مرّة.

**والاختبار بمصنّفات مبنيّة في الاختبار** لا بملفّات محفوظة: ملفٌّ ثنائيّ
مخزَّن لا يقول ما الذي يختبره ولا يُعدَّل لاختبار حالة. والبنّاء يجعل كل
حالةٍ صريحة — نصّ ممتدّ على `CONTINUE`، وخليّة غائبة في منتصف صفّ، وصفّ
مجاميع في الآخر.

**PDF وحده باقٍ** — استخراج نصّ الجدول بترتيب الأعمدة، ثمّ `normalizeRows`.
و`pdfjs-dist` في المشروع أصلًا فلا اعتماد جديد.

## 6 · الأعمدة المركَّبة — بادئةٌ لا قائمة

مسيرات الرواتب الحقيقية تفصّل البدل إلى «بدل سكن» و«بدل مواصلات» و«بدل
إعاشة»… والخصم إلى «تاخير» و«غياب» و«التامينات»… ولا تُدرَج قوائم بأسماء
بعينها: **أي عمودٍ يبدأ بـ«بدل» بدلٌ، و«خصم»/«استقطاع» خصمٌ** — فعمودٌ جديد
في مسير الشهر القادم يُفهم بلا تعديل كود.

والمجموع المُعلَن (`اجمالي الخصميات`) يسبق جمع الأجزاء حين يوجد الاثنان.

وثلاثة مجاميع يجب ألّا تختلط: `gross` (قبل الخصم) و`additions` (خارج
البدلات) و`net` (المستحقّ فعلًا). وخلطُ «اجمالي الراتب» بـ«صافي الراتب»
يجعل كل مقارنة تكذب بمقدار الخصميات — خطأٌ لا يظهر إلا لمن له خصم.

## 7 · صفّ المجاميع

آخر صفٍّ في كل مسير أرقامٌ بلا رقمٍ وظيفيّ ولا اسم. يُتخطّى ويُعدّ في
`meta.skippedRows` — ولا يُقرأ موظّفًا اسمه فارغ وراتبه مجموع الجميع.
