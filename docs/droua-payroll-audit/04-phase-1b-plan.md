## 2. قيد الدالّتين

```
api/app.js                    ← كل شيء يمرّ من هنا
api/cron/check-expirations.js ← لا تُمسّ
                              المجموع = 2
```

سطر التفويض في **أعلى** `module.exports = handler`، قبل أي منطق مشترك:

```js
// api/app.js — توضيحي
module.exports = async function handler(req, res) {
  const q = req.query || {};
  /* قسم المراجعة السرّي: تفويض كامل قبل أي منطق مشترك، و require كسول
     فطلبٌ غير ذروي لا يُحمّل شيفرة القسم أصلًا — لا في الذاكرة ولا في
     الـstack. المطابقة بادئةٌ كاملة لا احتواء. */
  if (q.page === SECURE_PAGE || isSecureApiPath(q.apiPath)) {
    return require("../lib/droua/router")(req, res);
  }
  ...
};

const SECURE_PAGE = "secure-audit";
function isSecureApiPath(p) {
  const s = String(p || "");
  return s === SECURE_PAGE || s.startsWith(SECURE_PAGE + "/");
}
```

**ثلاث قواعد على هذا الشرط:**
1. مطابقة **بادئة كاملة** — لا `includes()` ولا `startsWith("secure")`.
2. الموجّه **لا يرمي إلى الخارج أبدًا** (`try/catch` خاصّ)، فلا يبلغ
   catch-all في `api/app.js` الذي يُرجع `err.message`.
3. جدول توزيع **مختبَر صراحةً** يشمل أسماء مخادعة (§11 أ).

### ثمن القيد — بصراحة

| ما فُقد | التعويض |
|---|---|
| عزل على مستوى العملية | العزل منطقيّ: كل المنطق في `lib/droua/**`، والمشترك **باب عرضه أربعة أسطر** |
| حزمة نشر مستقلّة | `require` كسول: القسم لا يُحمَّل إلا لطلبه |
| catch-all مستقلّ | `try/catch` خاصّ لا يرمي |

**«لا خلط مع أجير» تبقى قائمة بالكامل** على مستوى الجداول والبيانات والمنطق
والاختبارات. المشترك هو الباب لا الغرفة.

## 3. الروابط — واسم لا يكشف شيئًا

| النوع | الرابط |
|---|---|
| الصفحة | `/secure-audit` |
| الـAPI | `/secure-audit/api/gate/{status,unlock,lock}` |

**⚠️ لاحظ: الـAPI تحت `/secure-audit/api/…` لا `/api/secure-audit/…`.**
سبب ذلك في §6 — وهو أثر مباشر لملاحظتك على الـCookie Path.

### `vercel.json` — سطران، بالترتيب

```json
{ "source": "/secure-audit/api/:path*", "destination": "/api/app?kind=api&apiPath=secure-audit/:path*" },
{ "source": "/secure-audit",           "destination": "/api/app?kind=page&page=secure-audit" }
```

الترتيب مقصود: مسار الـAPI **أوّلًا**. اليوم لا تعارض، لكن أي مسار
`/secure-audit/:something` يُضاف مستقبلًا سيلتقط `api` لو سبقه.

### فحص التسمية

لا `droua` · لا `payroll` · لا `salary` · لا `rawatb` — لا في الرابط، ولا في
اسم أي أصل يُطلب من المتصفّح. أسماء الملفّات على القرص وأسماء الجداول تبقى
صريحة (لا يراها مستخدم).

## 4. التصريح: الشرطان معًا

```
PROTECTED_USER_IDS      (قائم من المرحلة 1أ)
DROUA_AUDIT_USER_IDS    معرّف users.id المصرَّح له
DROUA_AUDIT_EMAILS      البريد المتوقَّع
```

```js
// lib/droua/access.js — توضيحي
function isAllowlisted(user) {
  if (!DROUA_IDS.length || !DROUA_EMAILS.length) return false;
  if (!protectedUsers.isConfigured()) return false;
  // كل مصرَّح له يجب أن يكون محميًّا أيضًا — الشرطان معًا لا أحدهما
  if (!DROUA_IDS.every(protectedUsers.isProtected)) return false;
  return DROUA_IDS.includes(user.id)
      && protectedUsers.isProtected(user.id)
      && DROUA_EMAILS.includes(String(user.email).trim().toLowerCase());
}
```

> **حماية الحساب وحدها لا تمنح وصولًا.** حسابٌ يُحمى غدًا لسببٍ إداريّ آخر
> لا يكتسب — بمجرّد حمايته — مسير رواتب سرّيًا. المنح يحتاج تأكيدًا صريحًا
> ثانيًا. والعكس صحيح: **نزع الحماية يقفل القسم ولا يكشفه**.

## 5. الجداول الثلاثة — أسماؤها ووظائفها

| الجدول | وظيفته | ما لا يخزّنه |
|---|---|---|
| `droua_gate_sessions` | جلسة البوابة المفتوحة — لتمكين الإبطال الحقيقي | ❌ التوكن الخام · ❌ IP · ❌ User-Agent |
| `droua_gate_attempts` | عدّ محاولات الفتح لتطبيق القفل | ❌ كلمة المرور ولا أي مشتقّ منها · ❌ IP |
| `droua_gate_audit` | تدقيق أمنيّ لأحداث البوابة | ❌ كلمة المرور · ❌ التوكن · ❌ IP خام |

**ثلاثتها تخصّ البوابة وحدها.** ⛔ **لا جدول لمسيرات ولا موظفين ولا ملفات
ذروة في هذه المرحلة إطلاقًا.**

> **تسمية:** الثالث كان `droua_payroll_audit` في التصميم الأصلي — **أُعيدت
> تسميته `droua_gate_audit`** التزامًا بقرارك. وهذا أفضل بنيويًا لا مجرّد
> امتثال: تدقيق **أمنيّ** للبوابة يختلف عن تدقيق **الأعمال** (رفع ملف، تشغيل
> مراجعة) في مدّة الحفظ ومن يقرؤه — فصلهما ميزة لا دَين.

### 5.1 `droua_gate_sessions`

```sql
CREATE TABLE IF NOT EXISTS droua_gate_sessions (
  -- المفتاح: sha256 لمعرّف الجلسة، لا المعرّف نفسه ولا التوكن.
  -- التوكن لا يُخزَّن إطلاقًا؛ والمعرّف داخله يُخزَّن مجزّأً — فتسريب
  -- القاعدة وحده لا يعطي شيئًا قابلًا للاستعمال.
  sid_hash      text PRIMARY KEY,
  user_id       text NOT NULL,             -- users.id
  issued_at     timestamptz NOT NULL DEFAULT now(),
  last_seen_at  timestamptz NOT NULL DEFAULT now(),
  idle_exp      timestamptz NOT NULL,      -- ينزلق: now + 15د، ولا يتجاوز absolute_exp
  absolute_exp  timestamptz NOT NULL,      -- يُثبَّت عند الفتح ولا يُمدَّد أبدًا
  revoked_at    timestamptz                -- الإبطال الحقيقي
);
CREATE INDEX IF NOT EXISTS idx_droua_gate_sessions_user ON droua_gate_sessions (user_id);
```

**سبعة أعمدة لا أكثر.** لا `ip` ولا `user_agent` ولا `ua_hash`: الربط بالـUA
حمايةٌ ضعيفة (يتغيّر مع كل تحديث متصفّح فيقطع جلسة مشروعة) ولا يمنع مهاجمًا
ينسخ الترويسة. فحذفهما يقلّل البيانات ولا يقلّل الأمان.

### 5.2 `droua_gate_attempts`

```sql
CREATE TABLE IF NOT EXISTS droua_gate_attempts (
  id        bigserial PRIMARY KEY,
  user_id   text NOT NULL,
  outcome   text NOT NULL,      -- 'fail' | 'success'  ← لا شيء عن كلمة المرور
  ts        timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_droua_gate_attempts ON droua_gate_attempts (user_id, ts DESC);
```

أربعة أعمدة. لا IP: الفاعل الممكن الوحيد هو الحساب المصرَّح له (كل من سواه
يُردّ بـ404 قبل بلوغ المُتحقّق)، فالعدّ لكل `user_id` كافٍ — ويمنع كذلك أن
يرفع غريبٌ عدّادي.

### 5.3 `droua_gate_audit`

```sql
CREATE TABLE IF NOT EXISTS droua_gate_audit (
  id       bigserial PRIMARY KEY,
  ts       timestamptz NOT NULL DEFAULT now(),
  event    text NOT NULL,
  user_id  text,
  meta     jsonb NOT NULL DEFAULT '{}'::jsonb,
  -- HMAC مقطوع إلى 16 حرفًا بمفتاح البوابة مع فصل مجال ("ip:"). ليس عنوانًا
  -- ولا يُعكس. غرضه واحد: أن أرى أن فتحًا وقع من جهاز لا أعرفه.
  ip_hash  text
);
CREATE INDEX IF NOT EXISTS idx_droua_gate_audit_ts ON droua_gate_audit (ts DESC);
```

**الأحداث في هذه المرحلة:** `access_denied` · `gate_unlock_success` ·
`gate_unlock_failed` · `gate_locked_out` · `gate_locked` ·
`gate_session_expired` · `section_opened`.

**⛔ ممنوع في `meta`:** كلمة المرور أو أي مشتقّ منها (ولا طولها) · التوكن ·
`sid` · الهاش · أي جزء من الإعداد. **الآلية قائمة مفاتيح مسموحة (whitelist)**
لا ممنوعة — فحقلٌ يضيفه أحدنا بعد سنة يُسقَط افتراضيًا. يفرضه اختبار يمرّر
`{password, token, sid, hash}` ويؤكّد أن الناتج `{}`.

على نمط `scripts/setup-payroll-monthly.js` حرفيًا: كل عبارة `IF NOT EXISTS`،

## 6. تصميم الـCookie — ملاحظتك كانت في محلّها

### المشكلة

الصفحة `/secure-audit` والـAPI `/api/secure-audit/...` **لا تشتركان في بادئة**
غير `/`. فكوكي بـ`Path=/secure-audit` **لا يُرسل** إلى `/api/secure-audit/...`
— البوابة تُفتح ثم تبدو مقفلة فورًا.

### الخيارات

| | الخيار | الحكم |
|---|---|---|
| أ | `Path=/` | يعمل، لكنه يرسل كوكي البوابة مع **كل** طلب إلى الأصل: `/`، `/api/data/*`، الأصول الثابتة. أوسع نطاق ممكن — عكس المطلوب |
| ب | كوكيان، `Path=/secure-audit` و`Path=/api/secure-audit` | ضيّقان، لكن قيمتان تُضبطان وتُمسحان معًا — وأي تباين بينهما عطلٌ صامت |
| **ج** | **نقل الـAPI تحت `/secure-audit/api/…`** | ✅ **المعتمد** |

### القرار: `Path=/secure-audit` — كوكي واحد يغطّي الاثنين

```
Set-Cookie: droua_gate=<token>; HttpOnly; Secure; SameSite=Strict; Path=/secure-audit; Max-Age=900
```

بنقل الـAPI إلى `/secure-audit/api/…` صار للصفحة والـAPI **بادئة واحدة**،
فكوكي واحد بأضيق نطاق ممكن يخدمهما.

**ويطابق قواعد RFC 6265 §5.1.4 بدقّة:**

| الطلب | يُرسل؟ | لماذا |
|---|---|---|
| `/secure-audit` | ✅ | مطابقة تامّة |
| `/secure-audit/api/gate/unlock` | ✅ | البادئة متبوعة بـ`/` |
| `/secure-auditXYZ` | ❌ | البادئة متبوعة بـ`X` لا `/` — لا تسرّب لأسماء مشابهة |
| `/api/data/employees` | ❌ | خارج النطاق |
| `/` والأصول الثابتة | ❌ | خارج النطاق |

**المكسب:** كوكي البوابة **لا يغادر مسار القسم إطلاقًا**. أي طلب إلى بقية
المنصّة لا يحمله — لا في ترويسة، ولا في وسيط، ولا في لوجّ.

### الخصائص الإلزامية

| السمة | القيمة | لماذا |
|---|---|---|
| `HttpOnly` | ✅ | لا يبلغه JavaScript — يحيّد XSS كمسار سرقة |
| `Secure` | ✅ | HTTPS فقط |
| `SameSite` | **`Strict`** | طلبٌ من موقع آخر لا يحمله — CSRF ينهار قبل أن يبدأ |
| `Path` | **`/secure-audit`** | أضيق نطاق يعمل للاثنين |
| `Max-Age` | 900 | ينتهي في المتصفّح، والخادم لا يعتمد عليه بحال |

### المهلتان

| | القيمة | الآلية |
|---|---|---|
| **خمول** | **15 دقيقة** | `idle_exp` ينزلق على كل طلب مصادَق عليه |
| **مطلق** | **60 دقيقة** | `absolute_exp` يُثبَّت عند الفتح و**لا يُمدَّد أبدًا** |

`idle_exp` الجديد = `min(now + 15د, absolute_exp)` — فلا ينزلق الخمول خارج
السقف بحال. ويُختبر بمحاكاة الزمن.

### ❌ لا تخزين محلّي

لا `localStorage` ولا `sessionStorage` ولا IndexedDB — لا للتوكن، ولا لحالة
«مفتوح»، ولا لعدّاد الوقت المتبقّي (يأتي من `expiresAt` في الردّ).

## 8. منع كشف الوجود

### 8.1 مصفوفة الـ404 — خمس حالات، **ردٌّ واحد**

| الحالة | الردّ |
|---|---|
| مسجَّل غير مصرَّح له | 404 |
| مصرَّح له لكنه **غير محميّ** (اختلّ الشرط الثاني) | 404 |
| `DROUA_AUDIT_USER_IDS` أو `DROUA_AUDIT_EMAILS` غائب | 404 |
| `PROTECTED_USER_IDS` غائب | 404 |
| `DROUA_GATE_SECRET` أو `DROUA_AUDIT_GATE_PASSWORD_HASH` غائب **أو صيغته تالفة** | 404 |
| `status !== 'active'` | 404 |
| خلل داخليّ في وحدة ذروة | **404** لا 500 |

**قرار مهم:** صحّة الإعداد — الوجود **وصيغة الهاش** — تُفحص في **طبقة
الحارس**، لا عند التحقّق. فإعدادٌ ناقص أو تالف يُخفي القسم كلَّه بدل أن
يُنتج فشلًا مميّزًا عند الفتح.

**والردّ مطابق بايتًا لما تنتجه المنصّة أصلًا:**
* الصفحات: `res.status(404).end("Not found")` — نفس `api/app.js:82`
* الـAPI: `{ok:false, error:"Not found"}` — نفس `api/app.js:72`

ليس 404 مصطنعًا يمكن تمييزه: نفس البايتات ونفس الرؤوس التي يراها من يكتب
`/xyz.html`. **ولا 403 بحال** — 403 يُقرّ بوجود ما يُحرَس.

### 8.2 الأسطح — كلّها مغلقة

| السطح | الحالة |
|---|---|
| ملفّ `.html` ثابت | ❌ لا وجود له — القالب في `lib/droua/views/*.js` (السبب في R-2) |
| ملفّ CSS/JS منفصل | ❌ مضمَّنان في الصفحة — فلا اسم أصل يظهر في لوجّ |
| `app-nav.js` | ❌ لا عنصر في `DEST`، ولا يُحمَّل في صفحات القسم أصلًا |
| شارة أو عدّاد | ❌ |

## 9. كلمة المرور الثانية — لا plaintext في أي مكان

### الصيغة المخزَّنة

```
DROUA_AUDIT_GATE_PASSWORD_HASH = "scrypt$17$8$1$<salt-hex>$<hash-hex>"
                                   │    │  │ │     │          └ 64 بايت
                                   │    │  │ │     └ 16 بايت عشوائية
                                   │    │  │ └ p (توازٍ)
                                   │    │  └ r (حجم الكتلة)
                                   │    └ log2(N) = 17
                                   └ الخوارزمية
DROUA_AUDIT_GATE_PEPPER        = "<32 بايت عشوائية>"   (موصى به)
```

الصيغة **مكتفية ذاتيًا**: تحمل الخوارزمية ومعاملات الاشتقاق والـsalt والهاش.
فترقية المعاملات لاحقًا لا تكسر التحقّق من هاش قديم.

### أين لا توجد كلمة المرور

❌ Git · ❌ قاعدة البيانات · ❌ متغيّرات البيئة (الهاش فقط) · ❌ اللوجّات ·
❌ التدقيق · ❌ HTML · ❌ JS · ❌ أي ردّ · ❌ **ولا تصل إليّ ولا إلى Claude**.

### التحقّق

```js
// lib/droua/gatePassword.js — توضيحي
const MAX_INPUT = 256;   // مدخل ضخم لا يُشتقّ منه شيء — يُعامل كخطأ عاديّ

function verifyGatePassword(input) {
  const stored = process.env.DROUA_AUDIT_GATE_PASSWORD_HASH;
  const parsed = parseHash(stored);              // الصيغة تُفحص في الحارس أيضًا
  if (!parsed || typeof input !== "string" || input.length > MAX_INPUT) return false;

  const peppered = crypto
    .createHmac("sha256", process.env.DROUA_AUDIT_GATE_PEPPER || "")
    .update(input, "utf8").digest();

  const candidate = crypto.scryptSync(peppered, Buffer.from(parsed.salt, "hex"), 64, {
    N: 1 << parsed.logN, r: parsed.r, p: parsed.p, maxmem: 256 * 1024 * 1024,
  });
  const expected = Buffer.from(parsed.hash, "hex");
  return candidate.length === expected.length
      && crypto.timingSafeEqual(candidate, expected);   // ثابت الزمن
}
```

* **`timingSafeEqual` لا `===`** — الشرط الذي طلبته.
* **`N = 2¹⁷`** (مقابل `2¹⁴` في `lib/auth/passwords.js`) ≈ 300ms للمحاولة.
  مقبول لعملية تقع مرّة في اليوم، ومكلف جدًا للتخمين الآلي.
* **`maxmem` مضبوط صراحةً** وإلّا رمى Node عند `N` كبير.
* **حدّ 256 محرفًا** يمنع استهلاك المعالج بمدخل ضخم.
* **الـpepper** يجعل الهاش المسرَّب وحده عديم الفائدة offline. حذفه ممكن
  ويكلّف هذه الخاصّية وحدها — لكن كلمة مرور يختارها إنسان تستفيد منه كثيرًا.
  ⚠️ فقدان الـpepper = يجب تعيين كلمة مرور جديدة.
* **صفر اعتماديات:** `node:crypto` وحده.

### توليد الهاش محلّيًا

```
node scripts/hash-gate-password.js
```
يقرأ من stdin **بلا echo** (لا تظهر على الشاشة ولا تدخل تاريخ الصدفة)،
ويطبع سطر الهاش وحده. بلا شبكة وبلا قاعدة. تُلصق القيمة في متغيّر بيئة
Vercel بخاصّية **Sensitive**. الإجراء الكامل في **§«توليد هاش البوابة»**
من الـRunbook.

## 10. الحماية من التخمين — بالأرقام

### السياسة

| فشل متراكم | خلال | القفل |
|---|---|---|
| **5** | 15 دقيقة | **15 دقيقة** |
| **10** | 60 دقيقة | **60 دقيقة** |
| **15** | 24 ساعة | **24 ساعة** + `critical` في التدقيق |

* **نجاح واحد يمسح العدّاد** (تُوسم صفوف الفشل السابقة مستهلَكة).
* **العدّ في Neon لا في الذاكرة:** كل طلب على Vercel قد يقع على نسخة دالّة
  جديدة أو متوازية — **عدّاد في الذاكرة ليس ضابطًا بل وهم ضابط**.
* **تقليم بلا كرون:** كل فتح ناجح يحذف الصفوف الأقدم من 30 يومًا.

### القفل للبوابة وحدها — شرطك المحوريّ

> **حساب المنصّة لا يُقفل ولا يُعطَّل ولا يُمسّ بحال.**

`droua_gate_attempts` جدولٌ مستقلّ، ولا شيء في مسار البوابة يكتب في `users`
ولا يستدعي `updateUser`. فحتى 15 محاولة فاشلة تُبقي دخولك إلى المنصّة يعمل
تمامًا — يُقفل القسم وحده. **ويفرضه اختبار يعدّ عبارات SQL: صفر كتابة على
`users`.**

### لا فرق في الردّ — شرطك الثاني

**ردٌّ واحد لكل أسباب الفشل:**

```
403  { ok: false, error: "تعذّر فتح القسم" }
```

| السبب | الردّ |
|---|---|
| كلمة مرور خاطئة | 403 · نفس الجسم |
| **قفل ساري** | 403 · نفس الجسم — **لا 429 ولا `retryAfter`** |
| مدخل أطول من 256 | 403 · نفس الجسم |
| إعداد ناقص أو تالف | **لا يبلغ هنا أصلًا** — 404 من الحارس (§8.1) |

**والتوحيد يشمل الزمن.** لو تخطّينا `scrypt` عند القفل لصار الردّ أسرع
بـ300ms — وهذا فرقٌ يُقاس. لذلك:

```
كل طلب فتح — ناجحًا كان أو فاشلًا أو مقفولًا — لا يعود قبل 600ms من بدايته.
```
القفل يتخطّى الاشتقاق (توفير معالجة) ثم ينتظر حتى الأرضية. والحساب العادي
يستغرق ≈300ms ثم ينتظر حتى الأرضية. **الاثنان يخرجان عند 600ms.**

⚠️ **الثمن — أقوله صراحة:** لن تعرف من الواجهة أنك مقفول؛ سترى الرسالة نفسها.
هذا ما طلبته وهو الصحيح أمنيًا. التخفيف: شاشة البوابة تعرض إرشادًا **ثابتًا
دائمًا** («إن تكرّر الفشل فانتظر قليلًا ثم أعد المحاولة») — يظهر في كل
الحالات فلا يميّز شيئًا. والسبب الحقيقي يبقى في `droua_gate_audit`.

### لا تسجيل لكلمة المرور ولا لمشتقّاتها

`droua_gate_attempts` يحمل `outcome` وحده — لا كلمة المرور، ولا طولها، ولا
أول حرف منها، ولا هاشها. و`droua_gate_audit` يمرّ بمُنقّي القائمة المسموحة.
و**ممنوع `console.log(body)` في الوحدة كلّها** — يفحصه اختبار نصّي.

## 11. الـFlow الكامل

### أ) زيارة `/secure-audit`

```
1. middleware.mjs        جلسة منصّة؟ لا → 302 /login.html  (سلوك كل مسار)
2. api/app.js            page === "secure-audit" → تفويض (require كسول)
3. lib/droua/headers     الرؤوس الأمنية على الاستجابة أيًّا كانت
4. lib/droua/access      ① requireUser → لا؟ 401 عام
                         ② الإعداد كامل وصحيح الصيغة؟ لا؟ 404
                         ③ id ∈ DROUA_AUDIT_USER_IDS ⋀ محميّ؟ لا؟ 404 + تدقيق
                         ④ email مطابق؟ لا؟ 404 + تدقيق
                         ⑤ status === 'active'؟ لا؟ 404
5. جلسة بوابة صالحة؟
     لا  → 200 + شاشة كلمة المرور (بلا أي بيان، وبلا اسم القسم)
     نعم → انزلاق idle_exp + 200 + صفحة «القسم مفتوح» + تدقيق section_opened
```

### ب) الفتح `POST /secure-audit/api/gate/unlock`

```
1-4. نفس الخطوات — الحارس يُعاد كاملًا، ولا شيء يُستنتج من التوكن
 5.  ابدأ عدّاد الأرضية (600ms)
 6.  أقفلٌ ساري؟  نعم → سجّل gate_locked_out → انتظر الأرضية → 403 عام
 7.  الطول ≤ 256؟ لا  → عامله فشلًا عاديًا
 8.  verifyGatePassword()  ← HMAC(pepper) ثم scrypt ثم timingSafeEqual
 9.  فشل → صفّ fail + تدقيق gate_unlock_failed → انتظر الأرضية → 403 عام
10.  نجاح:
       أ. sid = randomBytes(32)
       ب. صفّ في droua_gate_sessions بـ sha256(sid)
          idle_exp = now+15د · absolute_exp = now+60د
       ج. توكن موقَّع بـ DROUA_GATE_SECRET يحمل {sub, sid, exp, aexp}
       د. Set-Cookie … Path=/secure-audit; SameSite=Strict; HttpOnly; Secure
       هـ. امسح عدّاد الفشل + احذف ما تجاوز 30 يومًا
       و. تدقيق gate_unlock_success
       ز. انتظر الأرضية → 200 {ok, expiresAt, absoluteExpiresAt}
```

### ج) كل طلب لاحق

```
1-5. الحارس كاملًا مرّة أخرى  ← isAllowlisted لا تُخزَّن في التوكن أبدًا
 6.  توقيع التوكن بـ DROUA_GATE_SECRET؟ لا → مقفل
 7.  payload.sub === user.id؟           لا → مقفل
 8.  صفّ sha256(sid) موجود و revoked_at IS NULL؟ لا → مقفل
 9.  now < absolute_exp ⋀ now < idle_exp؟ لا → مقفل + تدقيق gate_session_expired
10.  انزلاق: idle_exp = min(now+15د, absolute_exp)  ← لا يتجاوز السقف أبدًا
11.  توكن جديد + Set-Cookie بنفس absolute_exp
```

### د) القفل `POST /secure-audit/api/gate/lock`

```
1. revoked_at = now()  على صفّ الجلسة  ← الإبطال الحقيقي
2. Set-Cookie: droua_gate=; Max-Age=0; Path=/secure-audit; (نفس السمات)
3. تدقيق gate_locked
4. 200 {ok:true}
```

**وتسجيل الخروج من المنصّة** يجعل الجلسة عديمة الأثر تلقائيًا (الخطوة ① في
الحارس تفشل). ومسحُ الكوكي عنده تحسينٌ اختياريّ بسطر واحد في `authLogout`.
