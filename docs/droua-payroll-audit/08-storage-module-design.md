# تصميم `lib/droua/storage.js` — أول وحدة في المرحلة 1ج

> **خطة، بلا كود.** لم يُكتب سطر بعد.
>
> **النطاق: البايتات وحدها.** رفعٌ مشفَّر، وقراءةٌ متحقَّق منها، وحذف. لا
> جداول، ولا واجهة، ولا قارئ، ولا محرّك مقارنة، ولا أي دلالة رواتب.
>
> **المراجعة الثانية (v2)** — بعد ملاحظتيك: هويّة ملفّ ثابتة في الـAAD،
> وحلقة مفاتيح حقيقية. وما تغيّر مُعلَّم بـ**‹v2›**.

## المبدأ الحاكم

> **الوحدة لا تعرف Neon، ولا تعرف HTTP.** تأخذ بايتات وتُرجع بايتات، وتُرجع
> واصفًا يحفظه غيرها. فتُختبر بلا قاعدة وبلا خادم، ويبقى لها سطحٌ واحد
> ضيّق يسهل تدقيقه.

## 1 · الواجهة المقترحة ‹v2›

```js
// lib/droua/storage.js

/* يشفّر ثم يرفع. يُرجع واصفًا للتخزين — لا يكتب في قاعدة ولا يعرفها. */
async function putEncrypted({ fileId, runId, kind, bytes, format })
  → { pathname, sizeBytes, plaintextSha256, encAlgo, encKeyId, encIv, encTag }

/* يقرأ ويفكّ ويتحقّق من الوسم ثم من البصمة. يُرجع بايتات النصّ الصريح. */
async function getDecrypted({ fileId, runId, kind, pathname,
                              encIv, encTag, encKeyId, plaintextSha256 })
  → Buffer

/* يحذف من المتجر. أفضل جهد: لا يرمي على «غير موجود». */
async function remove(pathname) → { removed: boolean }

/* نوع المحتوى الآمن المسموح تقديمه — من قائمة مغلقة لا من العميل. */
function safeContentType(format) → string

const MAX_BYTES, SAFE_CONTENT_TYPES, ALGORITHM, AAD_PREFIX
```

**خمس دوالّ لا غير.** ولا دالّة تُرجع رابطًا، ولا دالّة تقبل رابطًا — الرابط
غير موجود في هذه الوحدة أصلًا، لا مدخلًا ولا مخرجًا.

‹v2› **و`fileName` خرج من الواجهة كلّها.** لم يعد يدخل حتى كوسيط: لا المسار
يحتاجه ولا التشفير. مكانه القاعدة وحدها، والموجّه يقرؤه من الصفّ عند التنزيل.
فما لا يصل الوحدة لا يمكن أن يتسرّب منها.

### التوكن — الطبقات الأربع لإغلاق R-12

```js
function blobToken() {
  const token = process.env.DROUA_BLOB_READ_WRITE_TOKEN;
  //  ① الغياب يرمي — لا سقوط إلى الافتراضي بحال
  if (!token) throw new Error("تخزين القسم غير مُهيّأ");
  //  ② تساويه مع توكن أجير يرمي — يمسك خطأ اللصق مباشرةً
  if (token === process.env.BLOB_READ_WRITE_TOKEN) {
    throw new Error("توكن تخزين القسم يطابق توكن المتجر العامّ");
  }
  return token;
}
```

③ يُمرَّر **صراحةً** في كل نداء `put`/`get`/`del`.
④ واختبار عزل: لا ملفّ في `lib/droua/**` يذكر `BLOB_READ_WRITE_TOKEN` إلا في
هذا الفحص الواحد، وكل نداء Blob يحمل `token`.

> **لماذا كل هذا لسطرٍ واحد:** `@vercel/blob` يقرأ `BLOB_READ_WRITE_TOKEN`
> تلقائيًا حين لا يُمرَّر `token`. فالنسيان يقع **في اتجاه الخطر**: ملفّ
> رواتب سرّيّ يُكتب في متجر أجير العامّ، بلا خطأ وبرابط يفتحه أي أحد.

## 2 · الهويّة والـAAD ‹v2›

### كنتَ محقًّا: `runId|kind` غير كافٍ

التصميم الأول ربط الشيفرة بـ`${runId}|${kind}`. وذلك يمسك تبديل الشهور
والأنواع، لكنه **يترك ثقبًا في الحالة الأكثر وقوعًا**: إعادة رفع ملفّ
لتصحيحه. فحين يوجد ملفّان لنفس الشهر ونفس النوع — الأصل وبديله — يكون
الـAAD **متطابقًا بينهما**، فتبديل `blob_pathname` بين صفّيهما يمرّ من
توثيق GCM بلا شكوى، ويُقرأ الملفّ المسحوب مكان المعتمد.

وهذه ليست الحالة النادرة، بل الحالة التي بُني الاستبدال من أجلها.

### الـAAD النهائي

```
AAD = `droua-payroll-file|v1|${fileId}|${runId}|${kind}`      (UTF-8)
```

أربعة عناصر، **كلّها تُقرأ من صفّ القاعدة، ولا واحد منها يأتي من الطلب.**

| الجزء | لماذا هو موجود |
|---|---|
| `droua-payroll-file` | فصل مجال: شيفرة من سياق آخر بالمفتاح نفسه لن تُفكّ هنا |
| `v1` | نسخة الصيغة — تغييرها لاحقًا يبقى قرارًا صريحًا لا انزلاقًا |
| `fileId` | **الهويّة الثابتة** — تمسك التبديل داخل نفس الشهر والنوع |
| `runId` \| `kind` | تجعل عمودَي الصفّ نفسيهما غير قابلين للتحوير |

> **الفائدة الثانية غير المقصودة:** بما أن `run_id` و`kind` داخل الـAAD،
> فتعديلهما في القاعدة — بخطأ استعلام أو بيدٍ — **يكسر فكّ التشفير**. صار
> عمودان في جدولٍ عاديّ محميَّين تشفيريًّا بلا أي آلية إضافية.

و`AAD_PREFIX` مثبَّت باختبار: تغييره حرفًا واحدًا يجعل **كل ملفّ مخزَّن غير
قابل للقراءة**، وهو نوع الخطأ الذي لا يظهر إلا بعد النشر.

### شكل `fileId`

```
fileId = crypto.randomUUID()        ← يُولَّد قبل التشفير، لا بعده
       = المفتاح الأساسيّ id في droua_payroll_files
```

**أربع قواعد تحكمه:**

1. **يُولَّد قبل التشفير** — فالتشفير لا يبدأ بلا هويّة. و`putEncrypted` يرفض
   العمل إن غاب أو خالف صيغة UUID.
2. **ثابت لا يتغيّر أبدًا.** لا تحديث له في أي مسار.
3. **لا يُعاد استعماله.** الاستبدال يُنشئ `fileId` جديدًا وصفًّا جديدًا —
   لا يكتب فوق القديم. فالنسختان تبقيان متمايزتين تشفيريًّا.
4. **لا يأتي من العميل** — لا في الرفع ولا في التنزيل. في الرفع يولّده
   الخادم، وفي التنزيل يُقرأ من الصفّ الذي عثر عليه الموجّه.

### ولماذا `blob_pathname` ليس هويّة

```
droua-payroll-audit/<YYYY-MM>/<32 حرفًا hex عشوائية>
```

المسار **موضع، لا هويّة**. وهذا مقصود: عند إعادة التشفير بمفتاح جديد
(القسم 3) يُكتب كائن جديد بمسار جديد ويُحدَّث الصفّ — بينما `fileId` لا
يتغيّر، فيبقى الـAAD صالحًا ولا شيء في الهويّة يتحرّك. لو كان المسار هو
الهويّة لوجب حينها الكتابة فوق الكائن نفسه، وهي العملية التي لا تملك
تراجعًا إن انقطعت.

**⚠️ ولا اسم الملفّ الأصليّ في المسار، ولا نوعه.** المسار الأول في التصميم
كان `.../<kind>/<random>-<safe-name>` — وهو يسرّب المحتوى لمن يرى قائمة
المتجر: «مسير الرواتب كامل سبتمبر.pdf» يقول كل شيء بلا فكّ تشفير. ويبقى
الشهر للتجميع التشغيليّ، وهو أقلّ ما يُفصح.

> وكون المسار **عشوائيًّا لا معنى له** هو ما يجعل تسجيله في التدقيق سليمًا
> (القسم 6) — لا يكشف شيئًا عن محتواه.

## 3 · حلقة المفاتيح والتدوير ‹v2›

### كنتَ محقًّا هنا أيضًا

`enc_key_id = "k1"` مع متغيّر واحد `DROUA_FILE_KEY` **ليس تدويرًا**، بل عمود
يحمل ثابتًا. أول تدوير حقيقيّ كان سيصطدم بالسؤال: أين يعيش المفتاح القديم؟
ولا جواب — فتصير الهجرة إجبارية على كل ملفّ.

### الشكل: متغيّر مستقلّ لكل مفتاح

```
DROUA_FILE_ACTIVE_KEY_ID = k1
DROUA_FILE_KEY_K1        = <64 محرفًا hex>
DROUA_FILE_KEY_K2        = <64 محرفًا hex>     ← يُضاف يوم التدوير، لا اليوم
```

**لماذا متغيّر لكل مفتاح لا كائن JSON واحد يجمعها:** التدوير حينها
**إضافةُ متغيّر جديد**، ولا يُعاد كتابة المتغيّر الذي يحمل المفتاح القديم
أبدًا. أمّا حقل JSON واحد فيوجب لصق الكائن كاملًا في كل تدوير — ولصقةٌ
واحدة ناقصة تمحو `k1` **وتفقد معها كل ملفّ قديم بلا استرجاع**.

> **القاعدة:** لا يجوز أن يمرّ التدوير عبر تحرير القيمة التي تحمل المفتاح
> القديم. وهذا وحده يحسم الاختيار.

وواجهة `Environment Variables` في Vercel تعامل كل متغيّر على حدة، فهذا
الشكل هو الأوفق لها أيضًا.

### الواجهة

```js
// lib/droua/keyring.js  — وحدة صغيرة مستقلّة
keyring.load()            → { activeKeyId, ids }   // تحقّق شامل عند الإقلاع
keyring.activeKeyId()     → "k1"                   // للكتابة دائمًا
keyring.keyFor(keyId)     → Buffer(32)             // للقراءة، حسب صفّ القاعدة
```

**القواعد — كلّها fail-closed:**

* **الكتابة بالمفتاح النشط دائمًا**، ويُسجَّل `enc_key_id` مع الملفّ.
* **القراءة بمفتاح الصفّ** `enc_key_id`، لا بالنشط. ملفٌّ كُتب بـ`k1` يبقى
  مقروءًا بعد أن يصير النشط `k2`.
* **`enc_key_id` مجهول ⇒ يرمي.** ولا سقوط إلى النشط بحال — السقوط هنا يعني
  فشل فكّ صامتًا يبدو فسادًا في الملفّ، فيُشخَّص في الاتجاه الخطأ.
* **التحقّق عند التحميل:** معرّف بصيغة `^k[1-9][0-9]{0,2}$` · قيمة 64 محرفًا
  hex بالضبط · لا معرّفان بنفس المادّة (تدوير وهميّ) · النشط موجود في
  الحلقة · الحلقة غير فارغة. أي متغيّر `DROUA_FILE_KEY_*` مشوَّه **يرمي عند
  التحميل** ولا يُتجاوَز بصمت.
* **ولا اسم `DROUA_FILE_KEY` المجرَّد إطلاقًا** — الاسم بلا معرّف يدعو إلى
  سقوطٍ ضمنيّ، وهو صنف R-12 نفسه. حُذف الآن بلا تكلفة لأن عدد الملفّات صفر.

### إجراء التدوير — مصمَّم الآن، ويُنفَّذ يوم يُحتاج

```
① أضف DROUA_FILE_KEY_K2                     ← القديم لا يُمسّ
② اجعل DROUA_FILE_ACTIVE_KEY_ID = k2
   ⇒ الجديد يُكتب بـk2، والقديم يُقرأ بـk1 — ولا هجرة، ولا توقّف
③ (اختياريّ) كنسٌ تدريجيّ: لكل صفّ enc_key_id='k1'
     اقرأ بـk1 → اكتب كائنًا جديدًا بـk2 → حدّث الصفّ → احذف القديم
     و fileId لا يتغيّر ⇒ الـAAD لا يتغيّر
④ ولا يُحذف DROUA_FILE_KEY_K1 إلا بعد أن يصير عدّ الصفوف التي تشير إليه صفرًا
```

**والخطوة ④ هي الخطرة**: حذف مفتاح ما زال صفٌّ واحد يشير إليه = فقدان ذلك
الملفّ نهائيًّا. فتُشترط عليها استعلام عدٍّ في الـRunbook قبل الحذف.

**المفتاح في وعاء ثالث:** المتجر ثالث، والقاعدة ثانٍ، والمفاتيح في متغيّرات
البيئة. فمن يسرّب المتجر عنده شيفرة، ومن يسرّب القاعدة عنده وصفٌ بلا
بايتات. **ثلاثة أوعية، ثلاثة مفاتيح.**

### والتشفير نفسه

```
الخوارزمية : AES-256-GCM
IV         : 12 بايت عشوائية لكل ملفّ (المقاس القياسيّ لـGCM)
الوسم      : 16 بايت
```

## 4 · الواصف الذي يدخل Neon ‹v2›

الوحدة **تُرجعه ولا تكتبه**. تكتبه `lib/droua/files.js` لاحقًا في
`droua_payroll_files` (جدولٌ يُنشأ في خطوة تالية، لا الآن):

| الحقل | النوع | ملاحظة |
|---|---|---|
| `id` | `uuid` PK | **هو `fileId`** — يُولَّد قبل التشفير، ثابت، لا يُعاد استعماله |
| `run_id` | `uuid` | داخل الـAAD ⇒ تحويره يكسر الفكّ |
| `kind` | `text` | داخل الـAAD ⇒ كذلك |
| `blob_pathname` | `text` UNIQUE | موضع لا هويّة · **لا رابط — ولا عمود لرابط أصلًا** |
| `file_name` | `text` | الاسم الأصليّ — للعرض والتنزيل فقط، ولا يبلغ المتجر ولا الوحدة |
| `format` | `text` | `pdf` \| `xlsx` \| `xls` \| `csv` — من البايتات لا من الامتداد |
| `content_type` | `text` | من القائمة المغلقة، لا من العميل |
| `size_bytes` | `bigint` | بايتات **النصّ الصريح** قبل التشفير |
| `plaintext_sha256` | `text` | ‹v2› بصمة **الملفّ الأصليّ** — الاسم يقولها |
| `enc_algo` | `text` | `aes-256-gcm` |
| `enc_key_id` | `text` | `k1` … — **به تُقرأ**، لا بالنشط |
| `enc_iv` | `text` | hex — ليس سرًّا |
| `enc_tag` | `text` | hex — ليس سرًّا |
| `created_at` | `timestamptz` | |

**ولا يدخل القاعدة:** أي مفتاح · التوكن · رابط · أي بايت من المحتوى.

### ‹v2› `plaintext_sha256` — الاسم يحسم الالتباس

بصمة **النصّ الصريح قبل التشفير**. وسُمّي هكذا صراحةً لأن `sha256` مجرَّدًا
سؤالٌ مفتوح يُجاب عنه بالتخمين بعد سنة، والتخمين الخطأ هنا يعني مقارنة لا
تتطابق أبدًا فتُشخَّص كفساد ملفّ.

**فائدتان:** التحقّق من طرف إلى طرف بعد الفكّ (ضد عطلٍ في كودنا لا ضد
مهاجم — فالمهاجم يمسكه وسم GCM)، وكشف رفع الملفّ نفسه مرّتين.

و**لا بصمة للشيفرة**: وسم GCM يغطّي سلامتها بالفعل، وعمودٌ ثانٍ يوهم بحماية
مكرَّرة.

> **وملاحظة صريحة:** بصمة النصّ الصريح تصلح للتأكيد على محتوى **مُخمَّن**
> لمن يقرأ القاعدة. مقبولة هنا: القاعدة نفسها خلف بيانات اعتماد، وملفّ رواتب
> ليس ممّا يُخمَّن. لكنها مسجَّلة كي لا تُنسى إن دخل يومًا محتوى قابل للتعداد.

## 5 · استراتيجية التنزيل — ولماذا **لا** نبثّ

> **القرار: تُقرأ الشيفرة كاملة، ويُتحقَّق من وسم GCM، ثمّ تُرسل البايتات.
> لا بثّ للنصّ الصريح.**

**السبب أمنيّ لا تبسيطيّ.** وسم GCM لا يُتحقَّق منه إلا عند `final()` — أي
**بعد** آخر بايت. فالبثّ أثناء فكّ التشفير يعني إرسال نصٍّ صريح **غير
متحقَّق منه**؛ ولو فشل الوسم في النهاية لكان المتلقّي قد استلم بايتات
مزوَّرة بالفعل، ولا سبيل لسحبها.

فالبثّ هنا **يُبطل الغرض من GCM**. والحدّ الأقصى 10 MB هو ما يجعل الحجز في
الذاكرة آمنًا وبسيطًا.

```
GET /secure-audit/api/files/:id/download
  ① requireDrouaAccess(req, { needGate: true })     ← الحارس أوّلًا دائمًا
  ② اقرأ الصفّ من القاعدة  ← المسار والهويّة من القاعدة لا من الطلب أبدًا
  ③ get(pathname, { access:'private', token })       ← بتوكن القسم صراحةً
  ④ فُكّ + وسم + AAD + بصمة النصّ الصريح             ← أي فشل = 404
  ⑤ أرسل البايتات بالرؤوس القسرية
```

```
Content-Type: <من safeContentType(format) — لا من العميل ولا من الملفّ>
Content-Disposition: attachment; filename*=UTF-8''<مُرمَّز RFC 5987>
Cache-Control: no-store, private, max-age=0, must-revalidate
X-Content-Type-Options: nosniff
Content-Security-Policy: default-src 'none'; sandbox
Referrer-Policy: no-referrer
X-Robots-Tag: noindex, nofollow, noarchive
```

* **`Content-Type` قسريّ**: ملفّ يُقدَّم بـ`text/html` من نطاقنا يصير XSS
  مخزَّنًا في سياق يملك كوكي المنصّة **وكوكي البوابة معًا**.
* **`attachment` دائمًا**، ولا `inline` بحال.
* **اسم الملفّ يُنقّى من `\r` و`\n`** قبل الترويسة — وإلّا صار حقن ترويسات.
* **الفشل يُردّ 404** لا 500: رسالة مختلفة تكشف أن هنا ما يُعالَج.

## 6 · حدث سلامة داخليّ عند الفشل ‹v2›

> **العميل يأخذ 404 مطابقًا للـ404 العاديّ. والداخل يعرف بالضبط ما جرى.**

فالفساد الصامت أسوأ من الفساد المعلن: ملفٌّ يفشل فكّه اليوم ولا يُسجَّل، لا
يُكتشف إلا حين يُطلب بعد شهور — ووقتها لا أثر يقول متى بدأ ولا كم ملفًّا
أصاب.

```
event   : file_integrity_failure
outcome : fail
مسار    : audit.logStrict  ← لا logThrottled: الحدث نادر وكل وقوعة تعني شيئًا
```

**والإغراق غير وارد**، فالوصول إلى هذا المسار يمرّ أصلًا بـ
`requireDrouaAccess(needGate)` — أي أنت وحدك. ولذلك جاز هنا التسجيل الصارم
بلا خانق، بخلاف `access_denied` الذي يبلغه أي مستخدم مسجَّل.

### الحقول — توسعةٌ صريحة لقائمة `META_ALLOWED` في `audit.js`

| يُسجَّل | لماذا هو آمن |
|---|---|
| `fileId` | UUID لا معنى له خارج القاعدة |
| `runId`, `kind` | تصنيف لا بيان — بهما وحدهما يُعرف مدى العطل |
| `encKeyId` | يفرّق «مفتاح خطأ» عن «فساد بايتات» فورًا |
| `pathname` | عشوائيّ بحكم التصميم — ويلزم لكنس كائن يتيم |
| `reason` | من قائمة مغلقة: `tag_mismatch` · `sha_mismatch` · `unknown_key` · `object_missing` · `decrypt_error` |

**ولا يُسجَّل أبدًا:** `file_name` (اسمٌ كـ«مسير الرواتب كامل سبتمبر» بيانُ
رواتب لا واصف) · أي بايت · أي مفتاح · التوكن.

**وفشل كتابة التدقيق لا يحوّل الـ404 إلى 500** — الرد لا يتغيّر بحال.

## 7 · استراتيجية الحذف

### الاستبدال — الترتيب مُلزِم ‹v2›

```
fileId جديد → ارفع الجديد → أدرج/حدّث الصفّ → ثمّ احذف القديم (أفضل جهد)
```

**لا حذف قبل نجاح الرفع والكتابة.** انقطاعٌ في المنتصف بالترتيب الصحيح يترك
ملفًّا يتيمًا لا شهرًا بلا ملفّ. و‹v2› **النسخة الجديدة تأخذ `fileId` جديدًا
ولا تكتب فوق القديمة** — فتبقيان متمايزتين تشفيريًّا، وهو بالضبط ما يمسك
التبديل داخل نفس الشهر والنوع.

### الحذف — الصفّ أوّلًا

```
احذف الصفّ  →  ثمّ احذف الكائن (أفضل جهد)
```

**الاتجاه المعاكس أسوأ:** صفٌّ يشير إلى كائن محذوف يعني ملفًّا يظهر في
الواجهة ثم يفشل تنزيله — عطلٌ مرئيّ. أمّا الكائن اليتيم فغير مرئيّ.

### واليتيم غير ضارّ — بحكم التصميم

* **لا رابط له في أي مكان** (ولا عمود لرابط أصلًا).
* **مشفَّر**، والمفاتيح في وعاء ثالث.
* **ولا مسار يبلغه**: القراءة تبدأ دائمًا من صفٍّ في القاعدة.

فالكائن اليتيم **بايتاتٌ لا يعرف أحد أنها موجودة ولا يستطيع فكّها**. لذلك
`remove` أفضل جهد ولا يُسقط العملية — ويُسجَّل المسار في التدقيق عند الفشل
ليُكنس لاحقًا.

## 8 · الاختبارات الأمنية المطلوبة

### أ) التوكن — إغلاق R-12

1. `DROUA_BLOB_READ_WRITE_TOKEN` غائب → كل دالّة **ترمي**، ولا نداء يبلغ الـSDK.
2. مساوٍ لـ`BLOB_READ_WRITE_TOKEN` → **يرمي**.
3. كل نداء `put`/`get`/`del` يمرّر `token` صراحةً — يُقاس على النداء لا بالقراءة.
4. لا ملفّ في `lib/droua/**` يذكر `BLOB_READ_WRITE_TOKEN` خارج فحص التساوي.
5. `access: 'private'` مُمرَّر في **كل** `put` و`get`.

### ب) التشفير الأساسيّ

6. ما يُرفع **لا يساوي** النصّ الصريح، ولا يحتوي أي مقطع منه.
7. دورة كاملة: تشفير ← فكّ ← بايتات متطابقة تمامًا.
8. عبث ببايت واحد في الشيفرة → **يرمي**.
9. عبث بالوسم → يرمي.
10. IV مختلف → يرمي.
11. المفتاح والتوكن لا يظهران في أي رسالة خطأ.

### ج) ‹v2› الهويّة والـAAD — الثلاثة التي طلبتَها صراحةً

12. **تبديل بين شهرين** (`runId` مختلف، `kind` نفسه) → **يرمي**.
13. **تبديل بين نوعين** (`runId` نفسه) → **يرمي**.
14. **تبديل بين ملفّين لنفس الشهر ونفس النوع** (`fileId` مختلف وحده) →
    **يرمي** ← الثغرة التي أغلقها التعديل.
15. تحوير `run_id` أو `kind` في الصفّ دون الشيفرة → يرمي.
16. `fileId` غائب أو ليس UUID → `putEncrypted` يرفض **قبل** أي تشفير.
17. البايتات نفسها + `runId`/`kind` نفسهما + `fileId` مختلف ⇒ شيفرتان
    مختلفتان، ولا واحدة تُفكّ بـAAD الأخرى.
18. `AAD_PREFIX` يساوي `droua-payroll-file|v1` حرفًا بحرف ← تثبيت: تغييره
    يجعل كل ملفّ مخزَّن غير مقروء.

### د) ‹v2› حلقة المفاتيح

19. الكتابة تستعمل `activeKeyId` دائمًا، والواصف يحمله.
20. ملفٌّ كُتب بـ`k1` **يُقرأ بعد** أن يصير النشط `k2` — من `enc_key_id` لا من النشط.
21. `enc_key_id` مجهول → **يرمي**، ولا سقوط إلى النشط.
22. مفتاح مشوَّه (ليس 64 hex) → `load()` **يرمي عند التحميل**، ولا حلقة نصف صالحة.
23. `DROUA_FILE_ACTIVE_KEY_ID` غير موجود في الحلقة → يرمي.
24. معرّفان بنفس المادّة → يرمي (تدوير وهميّ).
25. حلقة فارغة → يرمي.
26. لا ذكر لـ`DROUA_FILE_KEY` المجرَّد في `lib/droua/**` (عزل، بشكل فحص R-12).
27. مادّة المفتاح لا تظهر في أي رسالة خطأ ولا في أي مخرَج.

### هـ) الحدود والمدخلات

28. أكبر من `MAX_BYTES` → يُرفض **قبل** التشفير.
29. بايتات فارغة → تُرفض.
30. المسار المولَّد لا يحوي `..` ولا `/` زائدة ولا أي اسم ملفّ.
31. اسم ملفّ فيه `\r\n` → مُنقّى قبل الترويسة (في الموجّه).
32. `format` خارج القائمة → يُرفض، ولا `safeContentType` يُرجع نوعًا من العميل.

### و) ‹v2› حدث السلامة

33. فشل الوسم → صفّ `file_integrity_failure` واحد بـ`outcome='fail'` و
    `reason='tag_mismatch'`.
34. اختلاف `plaintext_sha256` بعد فكّ ناجح → `reason='sha_mismatch'`.
35. `meta` المسجَّل لا يحوي `file_name` ولا بايتات ولا مفتاحًا ولا توكنًا.
36. رد الموجّه عند فشل السلامة **مطابق بايتًا بايت** للـ404 العاديّ — لا
    ترويسة فارقة ولا طول مختلف.
37. فشل كتابة التدقيق لا يحوّل الـ404 إلى 500.

### ز) التسريب والحارس

38. الواصف المُرجَع **لا يحوي حقل رابط**، ولا الوحدة تقبل رابطًا مدخلًا،
    ولا تقبل `fileName` أصلًا.
39. لا `console.*` في الوحدة يطبع بايتات أو مفتاحًا أو توكنًا.
40. الواصف يحمل `plaintextSha256` **ولا يحمل** مفتاحًا باسم `sha256` المجرَّد.
41. **لا مسار يبلغ `storage` قبل `requireDrouaAccess(needGate)`** — يُفحص على
    جدول التوزيع، فوحدةٌ تُستدعى من مسارٍ غير محروس تظهر في CI لا في الإنتاج.

**المتوقَّع: ~41 اختبارًا (كانت ~23)، والمجموع ~314.**

## 9 · المتغيّرات الجديدة (تُضبط عند التشغيل لا الآن) ‹v2›

```
DROUA_BLOB_READ_WRITE_TOKEN   توكن متجر droua-audit الخاصّ — ≠ BLOB_READ_WRITE_TOKEN
DROUA_FILE_ACTIVE_KEY_ID      k1
DROUA_FILE_KEY_K1             32 بايت hex — مفتاح AES-256-GCM
```

**وفقدان مفتاحٍ ما زال صفٌّ يشير إليه = فقدان تلك الملفّات نهائيًّا.** لا
نسخة منه في القاعدة ولا في المتجر — وهذا هو المقصود. تُحفظ المفاتيح في مدير
كلمات المرور مع الأسرار السابقة، **ولا يُحذف مفتاح إلا بعد عدٍّ يُثبت الصفر**.
