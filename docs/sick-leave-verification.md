# التحقق من الإجازات المرضية

صفحة مستقلّة `/sick-leave.html` (وحدة `lib/sickLeave/`) للتحقق من **أي** إجازة مرضية — موظفو ذروة، موظفو أجير، أو أي شخص آخر. لا تشترط `employee_eid` ولا تعرف أجير.

## Discovery: هل التكامل المباشر مع «صحة» ممكن رسميًا؟

**لا، في هذه المرحلة.**

| ما فُحص | النتيجة |
|---|---|
| API رسمي موثَّق للاستعلام عن الإجازات المرضية | لا يوجد API عام موثّق. صفحة `https://www.seha.sa/ui#/inquiries/slenquiry` تطبيق ويب (SPA) لبشر: المستخدم يُدخل **رمز الإجازة** (GSL/PSL…) و**رقم الهوية/الإقامة**، فتعرض الصفحة الإجازة (المدة، التواريخ، الاسم، الطبيب) |
| endpoint خلف الصفحة | أي نداء تستعمله الصفحة داخليّ وغير موثَّق ولا عقد له. استدعاؤه server-to-server هندسة عكسية لواجهة داخلية — ليس تكاملًا رسميًا |
| الشروط | شروط استخدام «صحة» تمنع الوسائل أو البرامج التي تعترض أو تحاول اعتراض التشغيل الصحيح للمنصّة أو تفرض عليها حملًا غير مناسب |
| CAPTCHA / anti-bot / session tokens | لم يمكن فحصها مباشرة: شبكة بيئة التطوير لا تسمح بالوصول إلى seha.sa. وفي كل الأحوال لا تُتجاوز، ولا فرق في القرار: لا عقد رسمي |
| بديل رسمي | الاستعلام عن إجازات الموظفين متاح للمنشآت عبر حساب المنشأة في «صحة» (واجهة بشرية). أي ربط آلي يحتاج عقدًا/مفتاح API رسميًا غير متوفّر حاليًا |

**القرار:** لا اتصال آلي بـseha.sa إطلاقًا — لا scraping، لا browser automation، لا تجاوز. نُفّذ البديل الآمن الذي يقترحه التاسك.

## التدفّق المنفَّذ

1. **رفع الملف** (PDF أو PNG/JPEG، حتى 4MB) → `POST /api/sick-leave/extract`. يُقرأ في الذاكرة على الخادم ويُترك.
   - PDF نصّي: تُستخرج الحقول من طبقة النصّ (pdfjs، اعتمادية قائمة): رقم الإجازة، الهوية، الاسم، البداية، النهاية، الأيام، وتاريخ الإصدار والمنشأة والطبيب والمسمى وجهة العمل والجنسية.
   - PDF ممسوح أو صورة: **لا OCR** (لا مكتبة محلية، والخدمات الخارجية ممنوعة لهذه البيانات) — يُدخل المستخدم الحقول المطبوعة يدويًا، ويُوسَم التحقق «إدخال يدوي».
2. **الاستعلام الرسمي**: زر يفتح صفحة «صحة» الرسمية في نافذة جديدة (`noopener noreferrer`)، وزرّا نسخ لرمز الإجازة ورقم الهوية. الصفحة SPA بلا معاملات تعبئة موثّقة، فلا تعبئة تلقائية.
3. **تسجيل ما أظهرته صحة**: «ظهرت الإجازة» (تاريخا البداية والنهاية، والأيام والاسم اختياريًا) / «لا توجد نتيجة» / «الخدمة غير متاحة» → `POST /api/sick-leave/verify`.
4. **النتيجة**:
   - `verified` — تم التحقق (✓ أخضر بتوهّج خفيف).
   - `mismatch` — الإجازة موجودة لكن الملف يختلف: كل فرق باسمه (رقم الإجازة / الهوية / البداية / النهاية / الأيام / الاسم) مع القيمتين.
   - `not_found` — صحة لم تُرجع إجازة بهذا الرمز وهذه الهوية.
   - `unavailable` — تعذّر التحقق حاليًا. **ليس** دليلًا على أن الإجازة غير صحيحة.

كل نتيجة تُعرض بمصدرها: «استعلام صحة الرسمي (أُدخل يدويًا)» — لا تُقدَّم على أنها استعلام آلي.

## المطابقة (`lib/sickLeave/compare.js`)

- **حاسمة، حرفية بلا تقريب**: رقم الإجازة (حروف كبيرة بلا مسافات)، الهوية (أرقام فقط)، البداية، النهاية (ISO). خانة واحدة مختلفة = مختلف.
- **الأيام**: تُقارن إن ذكرها الطرفان صراحةً.
- **الاسم** (تأكيد): مطابق بعد التطبيع (همزات، ة/ه، ى/ي، «عبد الله»/«عبدالله»، بن/ابن) ← match؛ اختلاف إملائي بسيط أو اسم مختصر داخل الكامل ← `name_minor_difference` تنبيه **لا يُسقط التحقق**؛ اسم مختلف فعلًا ← `name_mismatch`؛ لغتان مختلفتان ← لا يُقارن ويُعرض للمراجعة.
- الحقول المقروءة من الملف تعود داخل **توكن HMAC** (SESSION_SECRET، 30 دقيقة، مربوط بالمستخدم) فلا تُعدَّل من المتصفّح بين الخطوتين. الحقول التي لم تُقرأ وحدها يكملها المستخدم.

`lib/sickLeave/provider.js` يوحّد مصدر النتيجة الرسمية: أي عطل / مهلة / 429 / ردّ مشوّه ← `unavailable`. المصدر الوحيد المنفَّذ `seha_manual`. إن أُبرم عقد رسمي لاحقًا (API بمفتاح) يُضاف مصدر بالشكل نفسه ولا يتغيّر شيء آخر.

## الخصوصية

| ما | أين |
|---|---|
| ملف الإجازة | **لا يُخزَّن**: ذاكرة الدالّة أثناء الطلب فقط. لا Blob، لا قرص، لا Git، لا قاعدة |
| الحقول | تعود للمتصفّح الذي رفع الملف فقط (لنسخها إلى صحة). الهوية تُعرض مقنّعة `••••••9012` |
| audit_log | `sick_leave_extract`: بصمة HMAC للملف، النوع، الحالة. `sick_leave_verification`: verification id، الحالة، السبب، المصدر، الهوية مقنّعة، `leaveRef` (HMAC لرقم الإجازة)، أكواد الفروق، employeeEid إن وُجد، الفاعل والوقت. **لا** هوية كاملة، لا اسم، لا رقم إجازة صريح، لا محتوى |
| console | لا شيء من بيانات الإجازة |
| المتصفّح | لا localStorage/sessionStorage. «تحققات هذه الجلسة» في الذاكرة فقط |
| خدمات خارجية | لا AI، لا OCR خارجي، لا اتصال بـseha.sa من الخادم |

## الأمان

- النوع الحقيقي من التوقيع (`%PDF-`، PNG، JPEG)، والنوع المُعلَن يجب أن يتّفق معه.
- الحجم ≤ 4MB (تحت حدّ Vercel 4.5MB). PDF بلا `%%EOF` ← تالف.
- PDF bombs: رفض فوق 10 صفحات قبل القراءة، قراءة 4 صفحات كحدّ أقصى، 5000 عنصر نصّي، مهلة 8 ثوانٍ، `isEvalSupported:false`، `stopAtErrors`، ملف مشفّر ← رسالة واضحة.
- اسم الملف للعرض فقط (يُعقّم، لا يُستعمل مسارًا).
- الحدّ من الاستخدام من `audit_log` (Neon) لا من الذاكرة: 20 رفعًا و30 تحققًا لكل مستخدم في 10 دقائق ← 429 + Retry-After.
- التكرار: الملف نفسه خلال 30 دقيقة ← يُعلَّم «رُفع قبل قليل» ولا يُحجب.
- الصلاحيات: قسم جديد `sick_leave` بـ`view` (فتح الصفحة) و`verify` (رفع وتحقق). HR الاثنان، Owner/Admin الكل، Finance وViewer لا شيء.

## الربط بموظف (اختياري)

بعد التحقق، إن كان للمستخدم `employees:view`: رقم الهوية = `employees.iqama` حرفيًا وسجلّ واحد فقط ← يُعرض «مطابق لسجل موظف». قراءة فقط، ولا يمنع غيابُه التحقق.

## الرجوع

`git revert` لكوميت الميزة. لا بيانات تُنظَّف: لا جدول ولا متجر. صفوف audit_log من النوعين `sick_leave_*` تبقى سجلًّا تاريخيًا، أو تُحذف بـ`DELETE FROM audit_log WHERE type LIKE 'sick_leave_%'` إن أُريد.
